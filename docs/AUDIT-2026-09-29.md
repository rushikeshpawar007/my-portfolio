# Portfolio quality audit — 29 September 2026

This audit covers the local portfolio, legal pages, code, build and preview tooling, dependencies, links, motion, and visitor interactions. It preserves the existing palette and content. Changes have not been deployed.

## Issues corrected

| Finding | Result |
| --- | --- |
| The mobile bottom navigation obscured keyboard focus on the contact message field and footer links. At enlarged text sizes it also covered other controls. | The document reserves bottom scroll space, and focusing the textarea reveals its full box. The 84-stop keyboard tour found no obscured focus centre in desktop English, mobile English/German, or 320px German with doubled text; dedicated form/footer tests also check full control bounds. |
| At 320px with doubled text, the fixed masthead squeezed the name into a tall column and obscured later controls. | The name and theme/language controls can occupy separate rows, and narrow form controls have more space for their labels. |
| Bookmarks and browser history could point at the collapsed finance demo or its hidden source table. | Loading or returning to either fragment reveals the intended content. |
| If visibility observation was unavailable, early initialization could prevent unrelated controls from working. | Content and metrics settle visibly; navigation, contact, consent, demo and lineage controls remain usable. |
| Custom contact validation displayed a message while leaving keyboard focus on Send. | Focus moves to the field requiring correction. Failure paths retain the visitor's draft. |
| Short sample animations could continue in print media or after their disclosure closed. | Print and closure cancel those effects; print interactions stay static. Selecting the active reconciliation filter no longer replays an unnecessary animation. |
| Power BI linked to the monthly reporting case but its hover caption described deal history. | The caption now matches its destination. Hover still affects only the individual icon. |
| The contact email could break in the middle of its domain on narrow screens. | An optional break before `@` keeps the address easier to read without changing its destination or copied value. |
| Initialization rewrote translations that already matched, and language changes mixed metric geometry reads with style mutations. | Matching content stays intact, and metric visibility is read in one batch before applying state changes. |
| Theme switching suppressed transitions on every element and pseudo-element. | Suppression is limited to surfaces with colour transitions, preserving the existing cross-fade. |
| Local preview and brand export duplicated server code and handled malformed requests inconsistently. | Both use `scripts/serve.cjs`. `npm run preview` is the standard entry point; the previous test-server entry remains compatible. MIME types, HEAD responses, invalid paths and local cache behavior are covered by isolated tests. |
| Package metadata pointed at a nonexistent entry file; CI could miss accidentally focused tests. | Removed the stale entry, added `forbidOnly` in CI and retained failure diagnostics. |

The focus repair follows [W3C's scroll-padding technique](https://www.w3.org/WAI/WCAG22/Techniques/css/C43). Keyboard visibility and native controls were checked against the relevant [WCAG 2.2 guidance](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum); this is not a claim of comprehensive accessibility certification.

## Visitor interaction coverage

- Inventoried 112 links, buttons, disclosure controls, inputs and selectors, including conditional controls.
- Opened and closed all 11 ordinary disclosures through their controls, in four viewport/language/text-size configurations. No broken internal fragments or duplicate IDs were found.
- Walked 84 keyboard stops with the case studies expanded. The demo's separate keyboard interaction is covered by its own tests.
- Exercised navigation, language/theme switching, cookie choices and reopening settings, copy success/failure, demo prompts and cancellation, back-to-top, and contact validation, success, errors, timeout, retry and duplicate submission handling.
- Exercised 49 sample/link actions per language at 375×812, including all period, region and deal choices, reconciliation filters, data-cleaning steps and lineage controls. Tested pause/resume on all nine previews in each language.
- Checked all 17 skill/employer links by keyboard and one-tap touch. Project labels remain visible; unrelated icons remain unchanged on hover.
- Checked reduced motion, printing, missing JavaScript and unavailable animation/observer enhancements through targeted tests.
- Contact submissions and analytics were mocked during automated testing. No real contact messages were sent.

## Links and downloads

The local portfolio and both legal pages return HTTP 200 with HTML content types. The downloadable CV returns HTTP 200 as a valid 96,953-byte PDF. GitHub, Hashnode and all four certificate image viewers were verified publicly.

LinkedIn blocks automated access with an authentication wall/HTTP 999. Tableau returns HTTP 200 and its public application shell, but the visualization did not finish rendering during the bounded check. These destinations remain unverified; neither was established to be a broken link, so their URLs were retained.

## Code and folder organisation

The existing static-site layout remains appropriate: root-level hosted pages, application code in `src`, editable and generated CSS in `styles`, grouped media in `assets`, tooling in `scripts`, and checks in `tests`. No framework migration or arbitrary file moves were needed. Duplicate local server code was the concrete organisation issue addressed.

Dependencies were checked against the package registry: `npm audit` reported zero vulnerabilities, and `npm outdated` reported no outdated packages. No dependencies were added or upgraded. Browser automation remains a development dependency; the website ships vanilla JavaScript.

CI rejects focused tests and captures failure screenshots/traces, following [Playwright's test configuration guidance](https://playwright.dev/docs/test-configuration). Generated CSS is rebuilt and checked for consistency before publishing.

## Performance method

Resource inspection and local Chromium measurements cover initial loading, layout stability and real theme/language/disclosure interactions. Measurements are local lab samples with explicit throttling, not production field metrics or a physical 120 Hz device benchmark. A passing browser test is not evidence of 120 FPS.

The initial request inventory has one CSS bundle, deferred application scripts, self-hosted fonts and WebP images. It does not download the hidden dark portrait, old raster tool icons, GIFs, source stylesheets or legal-page stylesheet. All requested font faces have rendered uses, including the extended mono subset for the rupee symbol.

Performance interpretation follows [Google's Web Vitals guidance](https://web.dev/articles/vitals); the animation review follows [web.dev's rendering guidance](https://web.dev/articles/animations-guide). Production Core Web Vitals require real visitor measurements and cannot be certified from this local audit.

The [measured before/after comparison](PERFORMANCE.md#follow-up-quality-audit--29-september-2026) records lower theme/language click latency and less initial main-thread work. Unthrottled after-change controls recorded 48–144 ms clicks, but simulated CPU4× theme/language interactions still took 696–1,696 ms at the median. Loading results were mixed. Slower-device responsiveness remains a limitation, not a passed field-performance claim.
